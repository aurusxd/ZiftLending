# Zift — ТЗ на разработку (tech.md)

Сайт-визитка студии Zift. SvelteKit + TypeScript + Svelte 5 (runes), GSAP + ScrollTrigger, Tailwind CSS. Деплой: Vercel/Netlify.

Разработка ведётся вертикальными срезами (slices) — каждый слайс закрывает одну секцию/фичу целиком (компонент + стили + анимация), а не слоями "все стили → вся логика".

---

## Slice 0 — Инициализация проекта и design tokens

**Цель:** рабочий скелет проекта, из которого стартуют все остальные слайсы.

- `npm create svelte@latest` (SvelteKit, TypeScript, Svelte 5 runes)
- Установка: `tailwindcss`, `gsap` (+ `ScrollTrigger` плагин)
- `tailwind.config.ts` — design tokens вынесены в `theme.extend`:
  - `colors`: `background: '#0a0a0a'`, `accent: '#FF6A2E'`, `accent-light: '#FFB454'`, `text-secondary: серый (напр. #9CA3AF)`
  - `fontFamily`: sans-serif с широким кернингом для h1 (letter-spacing через кастомный class, не через сам токен шрифта)
  - `spacing`/`borderRadius` — общие токены для карточек (много воздуха, скругления)
- Структура папок:
  ```
  src/lib/components/sections/   (Hero.svelte, WhoWeAre.svelte, WhatWeDo.svelte, HowWeWork.svelte, Portfolio.svelte, Contact.svelte)
  src/lib/components/ui/         (переиспользуемые Button, Badge, Card)
  src/lib/gsap/                  (регистрация плагинов, общие утилиты ScrollTrigger)
  src/routes/+page.svelte        (сборка секций)
  static/hero/                   (видео-ассеты)
  ```
- Регистрация GSAP + ScrollTrigger в отдельном модуле, инициализация только на клиенте (`onMount`, т.к. SSR не должен пытаться трогать `window`)

**Готово, когда:** пустой лендинг с чёрным фоном рендерится локально и в build, токены применяются, ScrollTrigger подключен без SSR-ошибок.

## Slice 1 — Hero: три визуальных слоя + навбар

**Цель:** самая сложная часть сайта — три независимых слоя, не одно видео на весь экран.

### 1.1 Слой 1 — "небесная полоса" + навбар
- `position: fixed; top: 0; height: 72–80px; width: 100%`
- Внутри — `<video>` с облаком/молнией, `object-fit: cover; object-position: top`, обрезающий кадр так, чтобы облако легло ровно в полосу
- `<video autoplay muted playsinline>` — **без** `loop`
- По событию `ended` на видео → скрыть/остановить видео, показать ambient-слой (canvas или несколько `div` с CSS keyframes: мерцающие точки-звёзды со случайным `delay`/`duration` на каждую; редкие вспышки раз в 8–20 сек через `setTimeout` со случайным интервалом, `mix-blend-mode: screen` для доп. разряда)
- Навбар (лого, пункты меню, кнопка "Book a call") рендерится поверх этого слоя как обычный контент с `z-index` выше видео/canvas, полностью независим от анимации фона

### 1.2 Слой 2 — фон hero-секции
- Звёздное небо/градиент вниз, занимает всю hero-секцию под навбаром
- Скроллится обычно вместе с контентом (или fixed на весь первый экран — на усмотрение), но **не** масштабируется вместе с видео из слоя 1 — полностью раздельные DOM-узлы

### 1.3 Слой 3 — декоративные ромбы (SVG)
- Чистый SVG-компонент, без видео/растра
- Вложенные контуры-ромбы, только stroke (1–2px), без заливки
- Два кластера (лево/право), симметрично, `opacity: 10–25%`, цвет — акцентный оранжевый
- `z-index` между слоем 2 (фон) и текстовым контентом hero
- Опционально: GSAP-таймлайн на пульсацию opacity, синхронизированную с моментом удара молнии в видео (слушать `timeupdate`/конкретный тайм-код), + лёгкий parallax 10–20px на scroll через ScrollTrigger

### 1.4 Контент
- Заголовок по центру (H1, широкий кернинг): слоган Zift
- Подзаголовок
- Кнопки: "See Our Work" (заливка белым), "Book Discovery Call" (обводка)

### 1.5 Мобильная версия
- Вместо видео — статичный постер-кадр (последний кадр молнии), без autoplay-логики
- Слой 3 (ромбы) может упрощаться/скрываться на узких экранах при необходимости

**Готово, когда:** видео проигрывается один раз при загрузке, после `ended` включается ambient-слой без просадки FPS, навбар не зависит от видео, ромбы — чистый SVG с независимым parallax, на мобилке — статичный постер.

## Slice 2 — Who We Are (pinned overlay)

**Цель:** секция "наезжает" поверх Hero через `ScrollTrigger.pin`, а не просто скроллится следом.

- `ScrollTrigger.create({ trigger: '.who-we-are', pin: true, start: 'top top', end: '+=100%', scrub: true })` (или `pin` секции с анимацией `y`/`opacity` наезжающего контента поверх hero)
- Контент: бейдж "WHO WE ARE", заголовок "We build systems that learn, adapt and redefine" (часть текста — `<span class="text-accent">`), параграф-описание, 3 карточки-фичи в ряд (Full-Cycle Delivery, AI-First Engineering, Product Thinking) — иконка + заголовок + текст
- Карточки: скругления + `hover:` мягкое свечение (`box-shadow` с акцентным цветом, `transition`)

**Готово, когда:** при скролле секция визуально "накрывает" hero с эффектом смены сцены, а не обычным вертикальным потоком; корректно работает `unpin` при возврате скролла вверх.

## Slice 3 — What We Do (табы)

**Цель:** горизонтальные табы с плавной сменой контента.

- Табы: AI & ML Solutions, Full-Stack Engineering, Cloud Infrastructure, Data Engineering, Automation Systems, Product Design
- Состояние активного таба — Svelte 5 rune (`$state`)
- Контент таба: слева заголовок + описание + кнопка "Get started", справа — иллюстрация/иконка (SVG-анимация "чипа" с подписью LLM для AI-таба)
- Анимация смены: GSAP fade/slide при смене `activeTab` (timeline на `beforeUpdate`/эффект при изменении `$state`)

**Готово, когда:** переключение таба меняет и текст, и иллюстрацию с анимацией без "прыжков" layout.

## Slice 4 — How We Work (pipeline)

**Цель:** 4 шага в ряд, линия между ними заливается акцентным цветом по мере скролла до секции.

- 01 Discovery → 02 Architecture → 03 Build & Iterate → 04 Launch & Scale
- Каждый шаг: номер в рамке + короткое описание под ним
- Линия-коннектор между шагами: `scaleX` от 0 до 1 через `ScrollTrigger` (`scrub`) при входе секции во вьюпорт

**Готово, когда:** заливка линии синхронизирована со скроллом секции, на мобилке шаги складываются вертикально (линия — вертикальная заливка `scaleY`).

## Slice 5 — Portfolio

**Цель:** список проектов слева, превью справа, меняется по клику/hover.

- Список кликабельных карточек (иконка + название + короткое описание)
- Активный проект — `$state`, превью справа — крупный скриншот/макет, смена с fade-переходом
- Кнопка "View all projects →"
- Ленивая загрузка превью-изображений (`loading="lazy"` / динамический импорт)

**Готово, когда:** смена активного проекта работает по клику (и hover на десктопе), изображения не блокируют первичную загрузку страницы.

## Slice 6 — Contact / Lead Form + Telegram

**Цель:** форма записи на звонок с отправкой лида в Telegram.

- Поля: имя, email, дата (горизонтальный список дней), время (слоты), таймзона
- Клиентская валидация (обязательные поля, формат email)
- Сабмит → `+server.ts` (SvelteKit API route) → запрос к Telegram Bot API (`sendMessage`) с данными лида
- Токен бота и chat_id — переменные окружения (`.env`, не хардкодить)
- UI-фидбек: состояние отправки/успеха/ошибки на кнопке "Book a call"

**Готово, когда:** сабмит формы кладёт сообщение в Telegram-чат студии, невалидная форма не отправляется, есть явный успех/ошибка в UI.

## Slice 7 — Адаптивность и производительность

**Цель:** пройтись по всем секциям с прицелом на mobile-first и lazy loading.

- Проверка брейкпоинтов на всех секциях (hero уже упрощён в Slice 1.5)
- Ленивая загрузка: hero-видео (`preload="metadata"` или отложенный старт), изображения портфолио, тяжёлые SVG-анимации — через `IntersectionObserver`/`loading="lazy"`
- Аудит производительности ambient-слоя hero (canvas vs множественные div — выбрать по факту нагрузки)

**Готово, когда:** Lighthouse/PageSpeed не проседает из-за hero-видео и портфолио-изображений на мобильных сетях.

## Slice 8 — Деплой

**Цель:** рабочий деплой на Vercel/Netlify с учётом SSR/статики.

- Определить: секции с ScrollTrigger/GSAP — client-only (уже учтено в Slice 0 через `onMount`)
- `svelte.config.js` — адаптер под целевую платформу (`@sveltejs/adapter-vercel` или `adapter-netlify`)
- Env-переменные (Telegram bot token/chat id) — прописаны в настройках проекта на платформе, не в репозитории
- Проверка: SSR-страница не падает при отсутствии `window` на сервере (уже закрыто в Slice 0, перепроверить на билде)

**Готово, когда:** прод-билд успешно деплоится, форма лидов работает на проде (реальный Telegram bot token), hero-анимация работает в проде так же, как локально.
